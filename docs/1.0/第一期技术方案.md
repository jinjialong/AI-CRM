# 第一期技术方案

> 版本：第一版  
> 日期：2026-06-03

## 1. 方案说明

这份文档不讲复杂架构，只回答第一期最关键的技术选型问题：

- 前端用什么
- 后端用什么
- 数据库用什么
- 智能能力怎么接
- 部署怎么做

第一期目标是快速做出可演示版本，所以方案以简单、稳定、好落地为主，不引入太重的技术栈。

## 2. 技术选型总览

| 层级 | 选型 | 用途 | 说明 |
| --- | --- | --- | --- |
| 前端 | `Next.js 14` + `React 18` + `TypeScript` | 做页面、做智能助手界面、做前后端交互 | 现有项目已经在用，直接沿用最快 |
| 后端 | `FastAPI` + `SQLModel` | 做业务接口、权限校验、日志记录、智能编排 | 轻量、开发快，适合第一期 |
| 数据库 | `SQLite` | 存线索、客户、跟进、日志等业务数据 | 演示阶段够用，部署最简单 |
| 鉴权 | `JWT` | 做登录态和接口鉴权 | 简单直接 |
| 智能模型接入 | `OpenAI` 接口 | 做意图识别、字段提取、操作建议 | 第一阶段先接一个模型就够 |
| 部署方式 | `Docker Compose` | 本地和演示环境一键启动 | 前后端一起起，最省事 |

## 3. 前端方案

第一期前端建议直接用：

- `Next.js 14`
- `React 18`
- `TypeScript`

前端负责的内容主要有：

- 登录页
- 智能助手操作台
- 我的线索列表页
- 线索新建页
- 线索详情页
- 公共线索池页
- 我的客户列表页
- 客户详情页
- 系统管理页

前端实现原则：

- 页面先做实用，不追求复杂动效
- 智能助手页面按你要求，右侧是对话区，左侧是结构化结果区
- 第一阶段以前后端接口联调为主，不额外引入复杂状态管理方案

## 4. 后端方案

第一期后端建议直接用：

- `FastAPI`
- `SQLModel`

后端负责的内容主要有：

- 登录认证
- 用户和角色权限
- 线索管理
- 公共线索池流转
- 客户管理
- 线索跟进和客户跟进
- 联系人、拜访记录、沟通纪要
- 操作日志
- 智能助手动作执行

后端实现原则：

- 所有业务规则统一放在后端校验
- 页面操作和智能助手操作都走同一套后端接口和规则
- 转客户、删除这类关键动作必须在后端再次校验

## 5. 中间层方案

第一期不单独拆“中台”或单独的智能服务。

建议做法是：

- 智能编排能力直接放在后端服务里
- 由后端负责调用模型
- 由后端负责把自然语言转换成结构化参数
- 由后端负责决定是否执行真实业务动作

这样做的好处是：

- 架构简单
- 开发更快
- 业务规则不会分散
- 第一阶段更适合演示

## 6. 数据库方案

第一期数据库建议直接用：

- `SQLite`

原因很简单：

- 第一阶段是演示系统
- 不需要多公司隔离
- 不需要高并发
- 本地启动最方便
- 备份和迁移也简单

第一期主要数据表建议有：

- 用户表
- 角色表
- 线索表
- 线索跟进表
- 客户表
- 客户跟进表
- 联系人表
- 拜访记录表
- 沟通纪要表
- 操作日志表

后续如果系统继续扩大，再考虑切换到 `PostgreSQL`。

## 7. 智能能力方案

第一期智能能力建议这样接：

- 前端提供对话输入界面
- 后端接收用户自然语言
- 后端调用 `OpenAI` 模型
- 模型负责做意图识别、字段整理、内容总结
- 后端根据识别结果决定是查询、创建、编辑还是发起转客户

第一期智能助手建议支持这些动作：

- 创建线索
- 查询线索
- 整理线索跟进内容
- 查询公共线索
- 执行领取或分配相关动作
- 查询客户
- 整理客户跟进内容
- 发起转客户

关键规则：

- 创建和普通编辑可直接执行
- 转客户和删除类动作必须二次确认
- 所有智能动作都要写日志

## 8. 鉴权与权限方案

第一期建议：

- 账号密码登录
- 后端发 `JWT`
- 前端带令牌访问接口
- 后端按角色做权限控制

本期角色固定三类：

- 销售
- 销售经理
- 系统管理员

不做的内容：

- 不做自定义角色
- 不做一人多角色
- 不做复杂权限编排

## 9. 部署方案

第一期建议直接用：

- `Docker Compose`

启动结构很简单：

- 一个前端服务
- 一个后端服务
- 一个本地数据库文件

建议端口：

- 前端：`3000`
- 后端：`8000`

环境变量建议至少包含：

- 数据库连接地址
- 登录密钥
- 智能模型密钥
- 跨域配置

## 10. 第一阶段不引入的技术

为了保证第一期简单可落地，以下技术先不引入：

- `Redis`
- 消息队列
- 搜索引擎
- 对象存储
- 微服务拆分
- 多数据库拆分
- 多租户架构
- 独立智能中台

## 11. 当前结论

第一期最适合的技术方案就是一套轻量单体方案：

- 前端用 `Next.js 14` + `React 18` + `TypeScript`
- 后端用 `FastAPI` + `SQLModel`
- 数据库用 `SQLite`
- 智能能力用 `OpenAI` 接口
- 鉴权用 `JWT`
- 部署用 `Docker Compose`

这套方案的优点是简单、够用、开发快，最适合先把第一期演示闭环跑通。
