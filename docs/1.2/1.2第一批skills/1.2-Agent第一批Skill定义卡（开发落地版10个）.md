### 统一执行链路

```text
用户一句话
  -> 意图识别
  -> 选择技能包
  -> 读取当前对象/页面上下文
  -> 调用底层动作
  -> 返回结果 / 追问 / 确认
```

### 技能类型

- `read`：只读查询
- `draft`：先生成草稿，不直接落库
- `write`：写入或更新
- `dangerous`：高风险动作，必须确认

## 1. `query_leads`（查询线索）

### 1.1 基本信息

- 技能包名称：`query_leads`
- 中文名称：查询线索
- 所属业务域：线索
- 优先级：`P0`
- 类型：`read`
- 是否进入第一批：是
- 当前状态：部分已有

### 1.2 做什么

- 一句话：让用户直接查线索，不用自己切页面。
- 解决的问题：查“我的线索”“团队线索”“公共池线索”“线索详情”。

### 1.3 支持的动作

- `my`：我的线索
- `team`：团队线索
- `public_pool`：公共池线索
- `detail`：线索详情

### 1.4 开发落地

- 已有基础：`list_leads`、`list_public_pool`
- 需要新增：`get_lead_detail`、`list_team_leads`
- 前端交互：列表页 + 详情页 + 过滤条件

### 1.5 触发与上下文

- 典型说法：
  - 查一下我的线索
  - 看看团队线索
  - 查公共池
  - 打开这条线索
- 是否依赖页面：不强依赖，但详情最好能带 `lead_id`

### 1.6 输出

- 列表结果
- 详情结果
- 过滤条件摘要

### 1.7 验收

- 能查到用户有权限看的线索
- 能区分个人、团队、公共池
- 能打开单条详情

## 3. `write_lead_followup`（写线索跟进）

### 3.1 基本信息

- 技能包名称：`write_lead_followup`
- 中文名称：写线索跟进
- 所属业务域：线索
- 优先级：`P0`

## 11. 开发顺序建议

### 第一组先做

1. `query_leads`
2. `manage_lead`
3. `convert_lead`
4. `query_customers`
5. `manage_customer`

### 第二组再做

1. `write_lead_followup`
2. `manage_public_pool_lead`
3. `manage_my_report`
4. `draft_daily_report`
5. `query_team`

### 先不强行一次性做完的原因

- 一次性做完会把接口、交互、审计、确认链路拉得太散
- 先把主链路跑通，后面补包更稳

## 12. 这一版的开发口径

- 这份文档是第一批 10 个技能包的落地版
- 已有代码基础的，按现有接口继续补
- 还没有接口的，按这里补出新接口、新交互、新审计
- 后续如果技能继续扩展，再在这份文档上增量补，不重起一套
