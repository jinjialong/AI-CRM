## 3. 规则处理策略

### 3.1 直接保留

这些规则不应该删除：

- `confirm_action` 确认执行
- 权限校验
- 对象存在性校验
- 转客户业务约束
- 创建线索草稿显式会话延续
- 草稿放弃能力

### 3.2 逐步弱化

这些规则不建议继续扩写：

- `我的客户`
- `看看线索`
- `查客户`
- `公共池`
- 各种自然语言转客户表达

这些地方后续要更多依赖模型主理解，不再靠句式越堆越多。

### 3.3 当前优先替换

第一优先要优化的是：

- `R-03 is_list_customers_intent()`

原因：

- 第一批测试里 `我的客户` 已经暴露出模型主识别不稳
- 这个能力是高频查询能力
- 继续靠规则扩写收益低

## 4. 开发实施顺序

### 第一阶段：展示与监控解释收口

目标：

- 先让监控页、审计页对外展示变成人话中文
- 先把“兜底是什么”解释清楚

包含内容：

- 路由来源中文化
- 模型名中文化
- 动作和意图中文化
- 监控页保留总兜底率
- 明细里穿透看兜底原因分类

当前状态：

- `已开始`
- 已完成第一轮中文化

### 第二阶段：创建线索草稿会话收口

目标：

- 解决旧草稿污染
- 保留多轮补字段能力

包含内容：

- 不带 `session_id` 不自动续旧草稿
- 多轮补字段显式依赖同一 `session_id`
- 自动化测试创建类 case 先清草稿

当前状态：

- `已完成`

### 第三阶段：普通查询类识别弱化规则依赖

目标：

- 让普通查询更多靠模型主理解
- 不再继续扩句式规则

第一优先项：

- 查询客户

第二优先项：

- 查询线索
- 查询公共池

本阶段做法建议：

1. 先保留现有规则，不立刻删
2. 先观察真实测试里哪些短句经常被模型漏识别
3. 优先从提示词 / 上下文输入 / 意图分类稳定性入手
4. 跑出稳定结果后，再缩小本地规则覆盖面

### 第四阶段：高风险动作保护与模型理解拆层

目标：

- 不让高风险动作靠死规则理解
- 但仍然保留最终保护

建议保留的保护层：

- 对象绑定
- 权限校验
- 待确认动作
- 确认后执行

建议逐步弱化的部分：

- “转客户”的固定句式穷举

## 8. 当前执行口径

后续按这个口径推进：

1. 不再继续往普通查询里补越来越多句式规则
2. 高风险动作继续保留保护链路
3. 先用测试和监控找出模型最不稳的高频短句
4. 优先优化模型理解，不优先扩本地规则
5. 每动一层规则，都回到 `1.2测试-AI助手测试用例集.md` 对应用例重跑
