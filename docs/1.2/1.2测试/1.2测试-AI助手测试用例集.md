# 1.2测试-AI助手测试用例集

> 文档目的：沉淀当前 AI 助手已开发能力的测试用例，统一后续联调、验收、真实样本测试、Token 监控解释口径。
> 本文档不再讨论埋点方案，重点只放在“测什么、怎么测、期望什么结果”。

---

## 1. 适用范围

当前测试用例只覆盖 `POST /assistant/message` 主链路下，已经落地的这些能力：

- `create_lead`
  - 创建线索
  - 多轮补字段
  - 重复线索识别
- `list_leads`
  - 查询我的线索
  - 按公司名 / 状态 / 大区过滤
- `list_public_pool`
  - 查询公共线索池
  - 按公司名 / 状态 / 大区过滤
- `list_customers`
  - 查询客户
  - 按公司名 / 联系人 / 手机号搜索
- `convert_lead`
  - 明确编号发起转客户
  - 详情页上下文发起转客户
  - 确认执行转客户
- `show_config`
  - 查询基础配置
- `chat / unknown`
  - 普通回复
  - 未识别意图
  - 兜底与澄清回复

## 2. 测试目标

本批测试用例要回答 4 件事：

1. 业务动作能不能做对
2. 多轮会话能不能接上
3. 异常和边界条件会不会乱跑
4. 用户说一些不标准的话时，系统能不能稳住

---

## 4. 分批执行建议

当前文档共 `67` 条用例，不建议一次全跑。
后续执行按“第一批 / 第二批 / 第三批 / 第四批”来分，避免：

- 单次消耗过多 Token
- 一次性跑太久
- 问题定位困难
- 历史脏样本干扰判断

## 15. 当前已知风险说明

当前测试时需要特别注意这几个现实问题：

- 历史监控日志里已经混入过乱码输入样本
  - 例如 `?????????`
  - 这些样本会明显抬高“兜底占比”
- `详情页上下文转客户`
  - 当前是故意走规则兜底保障稳定性
  - 不应简单理解成模型能力差
- `确认执行 convert_lead`
  - 属于确认动作分支
  - 不走模型，Token 为 `0`
- 普通回复和未识别意图
  - 不能只看是否“成功返回消息”
  - 还要看有没有误写库、误转动作
