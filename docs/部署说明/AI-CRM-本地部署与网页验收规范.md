## 1. 目标

这份文档只解决一件事：

> 避免每次本地部署时，前后端端口漂移、实例混用、打开错网页、改了代码却看的是旧页面。

以后继续这个项目，先看这份文档，再启动服务、再打开网页。

本项目唯一有效目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM`

### 前端 API Base URL

---

## 4. 为什么后端固定用 8001

原因不是技术必须，而是本机现实环境需要规避冲突。

已确认的历史问题：

1. 本机 `127.0.0.1:8000` 曾被其他本地项目占用
2. 容易出现“代码改的是 AI-CRM，但浏览器实际连到另一个后端”的误判
3. 页面看起来像“改错了”，实际是连错服务

因此，这台机器上以后默认约定：

- `AI-CRM` 后端不用 `8000`
- 本地验收统一改用 `8001`

除非后续明确整体迁回 `8000`，并同步更新本文档，否则不要临时改回。

---

## 5. 本地部署默认规范

以后本地部署默认遵循下面 4 条：

1. 只保留一个 `AI-CRM` 前端实例
2. 只保留一个 `AI-CRM` 后端实例
3. 前端固定跑 `3200`
4. 后端固定跑 `8001`

禁止默认做法：

- 临时改成 `3000`
- 临时改成 `3105`
- 临时改成 `8000`
- 临时改成 `8002`
- 前端和后端各自漂到随机端口后不记录

## 6. 标准启动顺序

以后本地部署和页面验收，统一按下面顺序。

### 第一步：确认运行目录

项目根目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM`

### 第二步：确认旧实例

需要确认：

- `3200` 上没有旧的错误前端实例
- `8001` 上没有旧的错误后端实例
- 不要一边保留旧实例，一边再起一个新实例

原则：

- 如果是旧的 `AI-CRM` 实例，可以清掉再重启
- 如果是别的项目占着端口，不要偷偷换新端口继续验收

### 第三步：启动后端

工作目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM\src\backend`

启动命令：

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

### 第四步：启动前端

工作目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM\src\frontend`

推荐验收方式：

```powershell
Remove-Item -Recurse -Force .next
$env:NEXT_PUBLIC_API_BASE_URL='http://127.0.0.1:8001/api/v1'
npm run build
npm run start -- --hostname 127.0.0.1 --port 3200
```

说明：

- 做最终页面验收时，优先 `build + start`
- 不优先用 `next dev` 做最终验收
- 原因是这台机器上曾出现过 `next dev` 缓存和旧 bundle 混用问题

## 7. 打开网页前必须先核对的 5 件事

以后只要要“打开网页给用户看”，必须先核对：

1. 当前代码目录是不是 `AI-CRM`
2. 后端是不是跑在 `127.0.0.1:8001`
3. 前端是不是跑在 `127.0.0.1:3200`
4. 前端 API Base URL 是不是 `http://127.0.0.1:8001/api/v1`
5. 当前浏览器打开的，是不是这次刚启动的实例

只要有一项不确定，就先不要下结论说“页面坏了”或“改错了”。

## 9. 页面验收时的判断规范

以后“打开网页给用户看”时，默认按下面标准判断：

### 可用

满足以下条件可认定“页面已正确跑起来”：

1. 登录页可打开
2. 登录成功
3. 目标页面返回正常内容
4. 页面结构与当前代码版本一致
5. 不是旧 bundle，不是旧实例，不是别的项目

### 不可用

出现以下任一情况，不要直接说“代码坏了”，先排查运行实例：

1. 页面结构明显还是旧版
2. 页面标题、菜单、接口数据与当前代码不一致
3. 前端能打开，但接口内容像另一个项目
4. 改了代码，页面完全没变化

这类问题优先怀疑：

- 打开的不是当前前端实例
- 前端连错了后端
- 端口被别的服务占用
- 旧实例没关

## 10. 端口冲突时怎么处理

以后端口冲突默认按下面规则处理：

### 规则 1

不要把“换一个新端口继续跑”当成默认解决方案。

### 规则 2

优先确认占用端口的到底是不是 `AI-CRM` 自己的旧实例。

### 规则 3

如果不是 `AI-CRM`，不要静默漂移端口。

应该做的是：

1. 明确告诉用户当前默认端口被谁占了
2. 优先清理错误实例或无关冲突
3. 如果必须临时改端口，必须同时记录：
   - 新前端端口
   - 新后端端口
   - 新 API Base URL
   - 使用原因

### 规则 4

如果出现临时端口方案，任务结束前应把端口恢复到本文档标准，或者更新本文档。
