# AI-CRM 本地运行约束说明

## 目的

这份说明用于约束 Codex 或其他协作者在本机继续操作 `AI-CRM` 项目时的运行方式，避免出现：

- 改了 `AI-CRM` 的代码，但浏览器打开的是别的项目
- 同时存在多个前端实例，导致页面和代码不一致
- 端口混乱，接口和前端串错
- `next dev` 脏缓存导致页面异常或行为失真

后续如果要继续这个项目，优先把这份文件发给协作者，让对方先按这里执行。

---

## 项目根目录

本项目唯一有效目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM`

注意：

- 同级目录下还存在其他项目，例如：
  - `C:\Users\Administrator\AI编程\AICRM\sfa-crm-master`
- 后续所有代码修改、启动、检查，都必须确认是在 `AI-CRM` 目录下执行
- 不要把 `sfa-crm-master` 当成当前项目

---

## 本地运行原则

### 1. 单项目原则

只操作 `AI-CRM`，不要混用同级的其他 CRM 项目。

### 2. 单前端实例原则

同一时间只允许保留一个 `AI-CRM` 前端实例。

禁止同时存在：

- `next dev --port 3105`
- `next dev --port 3200`
- `next start --port 3200`

尤其不要在旧的 `dev` 实例还活着时，再起新的 `start` 实例。

### 3. 单后端实例原则

同一时间只保留一个 `AI-CRM` 后端实例。

建议固定：

- 后端：`127.0.0.1:8000`
- 前端：`127.0.0.1:3200`

### 4. 优先使用生产模式验证页面

当任务目标是“确认页面最终效果”而不是“边写边热更新”时：

- 不要优先用 `next dev`
- 优先用：
  1. 清理 `.next`
  2. `npm run build`
  3. `npm run start -- --port 3200`

原因：

- `next dev` 在这台机器上出现过缓存脏掉的问题
- 曾出现：
  - `Cannot find module './819.js'`
  - 页面 `500`
  - 路由能开但内容不是最新代码

## 固定端口约定

### 前端

固定使用：

`http://127.0.0.1:3200`

### 后端

固定使用：

`http://127.0.0.1:8000`

### API Base URL

前端环境变量必须指向：

`NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000/api/v1`

不要再指向：

- `8002`
- `3000`
- 其他临时端口

## 推荐启动顺序

### 第一步：确认没有旧实例

检查并清理：

- `AI-CRM` 的前端 `node` 进程
- `AI-CRM` 的 `uvicorn` 后端进程
- 占用 `3200` 的旧前端
- 占用 `8000` 的旧后端

重点：

- 只清理和 `AI-CRM` 有关的进程
- 不要误杀其他无关项目

### 第二步：启动后端

工作目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM\src\backend`

启动方式：

`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`

### 第三步：清理前端缓存

工作目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM\src\frontend`

删除：

`.next`

### 第四步：构建前端

工作目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM\src\frontend`

执行：

`npm run build`

### 第五步：启动前端

工作目录：

`C:\Users\Administrator\AI编程\AICRM\AI-CRM\src\frontend`

执行：

`npm run start -- --port 3200`

## 已知风险

### 1. 工作区有多个相似项目

同级存在：

- `AI-CRM`
- `sfa-crm-master`

如果没有明确校验项目路径，极易改错目录。

### 2. 旧前端实例容易残留

曾出现：

- 代码已经改了
- 浏览器打开的却还是旧页面

根因通常是：

- 老的 `next dev` 还占着端口
- 新的 `next start` 没真正接管

### 3. `next dev` 曾出现脏缓存

历史问题包括：

- `Cannot find module './819.js'`
- `/login` 返回 `500`
- 构建通过但运行内容异常

因此在验收页面时不要优先相信 `dev` 实例。

## 后续协作要求

下次继续操作这个项目时，先执行以下判断：

1. 当前目录是不是 `AI-CRM`
2. 当前前端是不是只保留一个实例
3. 当前后端是不是只保留一个实例
4. 前端是不是跑在 `3200`
5. 后端是不是跑在 `8000`
6. `.env.local` 是否指向 `8000/api/v1`
7. 页面是否来自最新 `build + start`

如果以上任一项不确定，先不要改业务代码，先清理运行环境。
